技术一面，大概五十多分钟。先自我介绍，我讲了学历、现在这家公司一年三个月、两个生产项目，还有一个 AI 项目。面试官先问线上遇到过什么问题。我讲了 [系统B] 的 Excel 表头校验写死、解析报错，还有人力工作量和财务薪资对不上，用五层 Map 做部门、项目、员工、金额小项、金额的映射。

然后问 [系统A] 遇到过什么问题。我说 Kafka 消费速度赶不上生产，任务积压；增加了消费者线程；在 Redis 里用 ZSet 存在途任务，还有一个控制队列，阈值 200，超过就暂停消费，低于 100 恢复；另外有 24 小时幂等标识。

面试官问有没有重复消费。我说没遇到；我们是手动提交，成功失败都提交，保证只消费一次；Redis 那个 24 小时标识类似分布式锁，但没有拿锁和解锁。

又问不用 Kafka 能不能做。我说只做任务可以，但系统七个模块都用 Kafka 解耦。

然后问 DeferredResult 怎么用。我说北向只能走 HTTP 回调，用异步转同步；十五秒超时；返回 messageId；前端轮询 Redis；释放 Tomcat 线程。

接着让我介绍 Agent 项目。我说用 Spring AI Alibaba 做 Supervisor、Planner、Executor，plan-execute-replan、observe，提示词控制流程；缺点是耗时长、token 成本高、计划会错、没有共享事实和约束、提示词写死；准备换 AgentScope 单 Agent。上下文压缩是六对消息压一次，效果不太好，会丢内容，阈值可配，也有总 token 水位压缩，强约束放代码或工具里。文档切片是 Markdown 按标题层级切，五十字符重叠；Office 先转文本或 Markdown；Excel 按行切、复制表头。

面试官问为什么向量加 BM25 加 RRF。我说向量语义相似但不精准，BM25 抓关键词，RRF 融合；实验下来小文档差别不大；后来觉得 RAG 没必要，skill、MCP 加 MySQL 就够了。又问我如果做企业知识库怎么支持上传、切片、检索。我说 Office 先解析，Excel 按行切、表头复制，可以加元数据；自然语言转 SQL 走 MCP 加 MySQL；复杂查询做视图或模板。

后面问平时怎么用 AI 写代码。我说需求先跟 AI 讨论，出方案，生成代码，编译测试，diff，提交，部署联调；复杂改动才走完整流程。面试官追问审查细不细，我说方案大体扫一眼，看得不细致。

最后问更想做 Java 还是 Agent。我说更倾向 Agent，但简历 Java 在前，因为生产项目都是 Java；Agent 那些 demo 不算上线，算不上正儿八经的项目。面试官问我对公司了解吗，我说了 [产品A]、Agentic workflow、Ontology，还问 Ontology 到底是什么、和 FDE 是不是类似。反问环节我问了团队规模、面试流程，还有 demo Agent 和生产 Agent 的差距。面试官讲了评测、真实场景、业务人员改结果、质量这些。最后问我怎么评测 Agent，我说十二个文档、几千切片，人工看引用路径和方案可行性，知道 RAGAS 但没引入。
