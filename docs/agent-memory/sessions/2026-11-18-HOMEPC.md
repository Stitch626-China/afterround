## 决策（为什么）

- **F3 状态机 6 态**：`PREPARING` / `IN_PROGRESS` / `GENERATING` / `SUBMITTED` / `COMPLETED` / `FAILED`。出题、追问生成、评估都是异步任务，用会话状态直接表达「任务执行中」，前端只轮询一个详情接口；评估细化状态仍由独立 `evaluateStatus` 承担。
- **追问异步生成**：作答主问题后会话短暂进入 `GENERATING`，前端轮询详情拿新追问。避免单次作答 HTTP 请求阻塞在 LLM 调用上。
- **题目统一序号 + parentIndex**：`questionIndex` 按实际呈现顺序连续编号，追问通过 `parentIndex` 指向主问题，既满足串行追问链，也方便前端直接按序渲染。
- **跳过主问题即跳过整条追问链**：没有主问题作答内容时追问无意义；跳过后直接进入下一主问题。
- **面试方向是动态列表不是契约枚举**：方向由 `skill.meta.yml` 定义，`GET /api/interview/directions` 返回 key，新增方向无需改契约。
- **模型切换复用 `40901` / `40902`**：与对话会话语义一致（任务执行中 / 终态锁定）；新增 `40911`~`40913` 只用于面试作答、跳过、交卷等状态守卫，`40914` 用于保留组上限。
- **Offer 对比由服务端产出固定矩阵**：`columns` + `rows`，行顺序和字段由服务端固定，缺失统一「未填写」，从结构上杜绝前端跨字段错位。
- **五险一金与补贴等保存原文**：基数 / 比例常见「按最低基数」「12%」等非纯数值写法，用字符串保留原文，避免过度结构化导致信息丢失；月薪、底薪、绩效占比用数值便于展示与比较。
- **Offer 提取走全局默认，分析走 `OFFER_ANALYZE`**：与 JD 解析 / 简历对比一致，提取不属于 7 个 `LlmScene`；前景与倾向分析进入场景级绑定。
- **Offer 分析同步且持久化最近一次结果**：与简历对比一致，不新增异步状态字段；详情接口直接返回最近分析结果。
