### 本地开发

- 配置项：`app.storage.root`，默认 `${STORAGE_ROOT:./data/files}`，相对于**后端进程启动目录**。
- 从 `backend/` 目录启动后端时，实际路径是：
  `backend/data/files/reviews/{uuid}.{mp3|wav|m4a}`
- 从仓库根目录用 `mvn -f backend/pom.xml spring-boot:run` 启动时，实际路径是：
  `data/files/reviews/{uuid}.{mp3|wav|m4a}`
- 简历文件：`resumes/{sha256}.{ext}`；JD 文件：`job-positions/{sha256}.{ext}`。
- 数据库 `review_sessions` 只保存相对 key（`audio_storage_key`）、原文件名与大小；接口不返回磁盘绝对路径。

### Docker Compose

- 容器内 `STORAGE_ROOT=/app/data/files`；
- `appdata` 命名卷挂载到容器 `/app/data`；
- 容器内路径：`/app/data/files/reviews/{uuid}.{ext}`；
- 宿主机实际位置由 Docker 卷管理，可用 `docker volume inspect` 查看。

### 生命周期

1. 上传音频时写入 `reviews/{uuid}.{ext}`，同时写 `review_sessions`；
2. ASR 从磁盘读取整段音频并转写；
3. 转写完成后音频**继续保留**，用于重试转写或留档；
4. 删除整条复盘时同步删除音频文件与分析/行动；
5. 目前**没有**「保留分析、只清理音频」的接口或按钮，也没有定时清理策略。

> 因此 NFR7 的「分析完成后音频可选清理」仍是缺口；如果音频长期累积，需要新增清理端点/按钮或定时策略。
